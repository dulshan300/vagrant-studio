# ADR-0005: Vagrantfile editing is conservative; raw mode is always authoritative

- Status: Accepted
- Date: 2026-10-28

## Context
Vagrantfiles are arbitrary Ruby. Full round-tripping would need a Ruby parser
and evaluator and still couldn't represent dynamic logic.

## Decision
- Visual editing applies only to files generated by Vagrant Studio (header
  marker plus model checksum) or files matched by a conservative recognizer
  for the supported subset.
- Everything else opens in raw mode; the visual view is read-only with an
  explanation.
- Every generated write shows a diff, writes atomically and keeps a backup.
  Imported Vagrantfiles are never replaced without explicit confirmation.
- Actual machine definitions come from Vagrant (`vagrant status
  --machine-readable` in the environment directory), not from our parsing.

## Consequences
- Users with complex Vagrantfiles get raw editing and lifecycle features, but
  not forms.
- No claim of full Ruby support is made anywhere in the UI or docs.

## Implementation notes (Phase 5, 2026-10-28)
- The header marker is `# vagrant-studio: sha256=<checksum of the rest>`.
  Recognized hand-written files and template files can be edited visually.
  A matching checksum only says whether the file was changed by hand since
  the editor wrote it.
- Backups go to the app data folder, not the project folder (the user's
  choice). Project folders and git status stay clean, but backups don't
  move with the project.
- Raw saves also show a diff, get a backup, and are checked against changes
  on disk.
- Details: `docs/vagrantfile-editor.md`.
